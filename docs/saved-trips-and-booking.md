## 使用方式

1. 在 AI 规划完成行程后，点回复下方「保存到行程」。也可以在行程页点「从聊天记录选择方案」，保存历史中的完整回复。
2. 填行程名称；出发日期可稍后填写。只在本机保存选中回复的副本，不调用 Gemini、Places 或新增云服务。删除聊天或继续修改聊天不会覆盖已选方案。
3. 行程中查看总结、路线概览、原始预算、每日景点和有序安排。Day 按钮切换每天；地图按钮打开该景点查询。预算沿用原回复的币种，不把历史人民币金额误标成日元。
4. 在某一天的「预订入口」选择酒店、机票、车票或门票/体验。核对住宿城市、出发与到达城市、日期、人数后加入待订清单。机票不能只写北海道，需明确札幌/函馆等城市；不自动替用户决定机场。新增酒店默认1晚，需要自行确认退房日期与实际住宿城市。
5. 从清单打开 Trip.com 网页，完成搜索、登录和购买。返回本 App 后手动勾选已预订。打开链接不表示已下单，也不读取 Trip.com 订单。
6. 「带着这份方案继续和 AI 讨论」生成新聊天草稿，不自动发送；保留城市、天数、人数、原预算和全部 Day 摘要。长安排会压缩为摘要，原行程不受影响。

## 网页与已搜索内容的边界

使用现有 Expo Go 自带 `expo-web-browser` 的 `openBrowserAsync` 在浏览器页面中打开 HTTPS。仅允许由代码构造 `www.trip.com` 官方地址，不接受 AI 返回的链接，不调用 Trip.com App 自定义协议。

链接附带 `wkp=0`：2026-11-09 检查 Trip.com 公布的 [iOS app-site-association](https://www.trip.com/.well-known/apple-app-site-association)，该参数被排除在其 Universal Links 的 App 打开规则之外。用户已确认中洲屋台街从 Expo Go 打开对应网页；其他入口仍需逐项真机确认。网页中用户主动点击“打开 App”属于 Trip.com 的行为。

第一版已核对的精确入口：

- [东京 → 札幌机票](https://www.trip.com/flights/tokyo-to-sapporo/airfares-tyo-spk/) 和 [札幌 → 东京机票](https://www.trip.com/flights/sapporo-to-tokyo/airfares-spk-tyo/)，城市全部机场，不锁定羽田/成田/新千岁某机场。
- [东京酒店](https://www.trip.com/hotels/tokyo-hotels-list-228/)、[札幌酒店](https://www.trip.com/hotels/sapporo-hotels-list-641/)、[京都酒店](https://www.trip.com/hotels/kyoto-hotels-list-734/)、[大阪酒店](https://www.trip.com/hotels/osaka-hotels-list-219/)。
- [东京 → 京都铁路](https://www.trip.com/trains/japan/route/tokyo-to-kyoto/)。
- [福冈中洲屋台街详情](https://www.trip.com/travel-guide/attraction/fukuoka/nakasu-food-stalls-street-145039597)，已核对官网标注 Free entry。支持中州/中洲、屋台街/屋台横丁名称；显示查看详情和参观安排，不称为已购票。
- [东京晴空塔介绍与购票入口](https://www.trip.com/travel-guide/attraction/tokyo/tokyo-skytree-91422)。

上述入口已定位城市/航线/景点，**不等于已完成带日期、人数和房型的实时库存查询**。日期、人数、成人儿童、房间数、车站机场需在 Trip.com 核对；卡片明确提示，并提供「复制查询条件」。目前不声称已经预填未验证参数。

其他城市、路线或景点进入 Trip.com 自身的带关键词搜索结果页（`/global-gssearch/searchlist/search?keyword=...`），关键词包含城市和项目名称，不再打开空白分类页。此入口于2026-11-09通过 Trip.com Travel Guides 搜索框真实提交验证，福冈中洲屋台街关键词产生相关结果。未收录项目明确显示是关键词结果而不是精确产品，结果可能仅为攻略，不能声称有售门票或班次；不会拼造产品 ID。可继续逐条核实官网入口并扩充 `src/lib/trip-booking-links.ts` 中的白名单。没有接入付费 API、合作联盟、实时价格、库存、支付、订单或佣金系统。

## 数据与限制

- 存储键 `japan-travel.saved-trips.v1`，最多20份方案；单份原回复最多14000字符、最多31天、150项清单，总序列化上限500000字符。
- 只保存明确列举字段、原始文本副本和人工维护的清单；不保存 Google Photos 资源、API 密钥或服务会话凭证。
- 所有日期按日历验证，日偏移使用 UTC 避免设备夏令时改变天数。修改出发日期只影响每日标签和以后新增事项的默认值，不自动移动已保存清单日期。
- 写入串行执行；设置修改与清单修改合并到最新记录，写入失败不覆盖旧记录。未知版本/损坏记录拒绝覆盖。
- 相同聊天与消息、相同文本再次保存时打开已有方案；同一聊天后续新回复另存新版本。删除行程需要两次点击确认，不删除聊天，也不取消已在 Trip.com 下的订单。
- 尚无账号或跨设备同步。清除 Expo Go 应用数据/重装可能丢失本机记录。
- 保存入口只接受当前支持的完整行程格式：Day 连续、每天有安排、有小结；概览天数不能与实际 Day 数不符。不把 AI 追问或截断回复当成完整行程保存。

## 队友在自己的电脑预览

从仓库根目录执行；先保留本机未提交修改，再同步工作分支。若没有本机修改，可使用：

```sh
git fetch origin
git switch feat/places-guided-planning
git pull --ff-only origin feat/places-guided-planning
cd japan-travel-mobile
npm ci
[ -f .env.local ] || cp .env.example .env.local
npx expo start --go --lan --clear
```

已有 `.env.local` 时不要直接覆盖，核对公开配置如下即可：

```dotenv
EXPO_PUBLIC_API_BASE_URL=https://japan-travel-chat-14289984868.asia-northeast1.run.app
EXPO_PUBLIC_CHAT_ACCESS_MODE=shared
```

使用支持本仓库 SDK 58 的 Expo Go；手机与自己的开发电脑连同一Wi-Fi，扫描该电脑终端生成的新二维码。LAN不通再用 `npx expo start --go --tunnel --clear`；tunnel可能另需Expo提示的隧道依赖。两位测试者可在不同Wi-Fi，各自启动Expo，连接同一云端AI服务。无需Gemini密钥、邀请或本地AI后端。

聊天记录、已保存行程和清单属于各设备的本机数据，不随GitHub代码同步；队友需要在自己的手机保存一份已有聊天方案。Expo Go仍依赖自己的开发电脑和正在运行的Expo服务，GitHub不会自动运行App。停止开发预览在对应终端按 Ctrl+C，不影响现有云端后端。
