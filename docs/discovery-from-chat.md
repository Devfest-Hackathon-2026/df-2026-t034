# 发现：授权封面与独立详情

本机改动沿用 Expo SDK 58、聊天历史与现有 Places 后端。普通浏览发现页、筛选、分页、打开详情均不连接聊天会话、不请求 Places，也不调用 Gemini。聊天页的生成和照片逻辑保留，旧素材映射只抽取成共用模块。

## 推荐与详情

- 重新进入发现时读取当前设备历史，选最近5段有AI回复的对话，每段取最新一份有城市/景点证据的方案，最多40个聊天地点。来源被删除后重新计算，不维护可遗留的独立用户画像。
- 搭配13个明确标为精选资料的固定地点，首批覆盖北海道、东京、京都、大阪。没有历史也能浏览精选资料，不假称AI已推荐或虚构用户帖子。
- 相同地区的精选地点按最近讨论的地区优先，准确匹配授权封面的地点优先展示；无图库匹配的原推荐仍可搜索，不用相邻景点照片冒充。
- 搜索城市、景点、介绍，忽略“北海道5天”等查询里的天数修饰。搜索不到时可将搜索词带入AI新草稿，保留旧对话，不自动发送。
- 卡片进入全屏景点详情，保留四个底部入口。详情包含资料照片、作者/许可/原始来源、推荐原因、已有介绍、原方案当日有序活动。资料照片标明已有拍摄年份，不声称实时画面。
- 地图入口打开Google Maps普通地点搜索链接，不调用本项目Places API。聊天来源的地点可回到原对话；精选地点可带名称进入AI草稿，不自动调用模型。

## 图片与额度

- 卡片和详情主图只用包内图片。`discovery-covers.ts`明确绑定地点和城市，`discovery-cover-photo.tsx`只接受本地数值素材引用；没有网络搜索或远程兜底。未知地点显示“资料图待补充”。
- 复用原有审核素材，补充大通公园、小樽运河、浅草寺雷门3张已检查图片。来源/作者/许可见 `japan-travel-mobile/assets/images/discovery/README.md`。新图片按各自原许可使用，卡片裁剪、详情完整画面展示；所有署名也注册到设置页。
- 只有详情里的“查看更多实景”按钮会建立/恢复现有匿名会话，并查询一个地点。快速连续点击共用同一次请求；成功后当前详情不重复查；限额用完停止；失败只在再次明确点击时重试。关闭详情取消后续工作，没有自动轮播或整页查图。
- Places实景仍遵守原100次/UTC日、80次/会话；一般一次搜索+一次取图，失败也可能计数，不重置计数。Google图片仅当前详情展示，保持原Google Maps、全部作者与政策入口，不保存成资料图库。没有增加API、权限、计费或部署变更。

## 预览

沿用 `.env.local` 公开HTTPS地址与shared模式，无需新增依赖或密钥。仓库根目录执行：

```sh
cd japan-travel-mobile
npm ci
npx expo start --go --lan --clear
```

手机与自己的Expo电脑连同一Wi-Fi，扫描自己终端新生成的二维码；不要使用队友电脑的旧IP地址或二维码。换Wi-Fi后需重启Expo并重新扫码。已有项目在Expo Go中重新加载，刷新Trip.com网页不会更新App代码。普通浏览不消耗Places/Gemini额度；主动点实景入口才使用图片额度，用户发送AI消息才使用聊天额度。

参考：[Expo Router SDK58](https://docs.expo.dev/versions/v58.0.0/sdk/router/)、[Expo Image SDK58](https://docs.expo.dev/versions/v58.0.0/sdk/image/)、[Places内容与署名要求](https://developers.google.com/maps/documentation/places/web-service/policies)。

代码已与行程及 Trip.com 网页入口一起整理供 GitHub 协作，手机配置沿用 `.env.example` 中的公开云地址与 shared 模式，不需要启动本地 AI 后端。
