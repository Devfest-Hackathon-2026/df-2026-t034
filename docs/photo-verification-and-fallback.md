# 跨城市景点图片核对与缺图反馈

此次只修改手机图片模块，保留已有 Gemini 提示词、行程/预算/渐进展示、Cloud Run 配置和额度。不依赖模型口头宣称图片存在；实际查询结果决定是否显示照片。

## 修复与流程

截图中的宇都宮二荒山神社有正确照片，但日语维基的许可为 `パブリック・ドメイン`，旧代码只接受英语 `Public domain` 而错误隐藏。现将已识别的公共领域本地化许可规范化，并支持常见 CC 2.5 / 2.1 JP 版本。仍拒绝不明许可、非自由许可、不可信图片域名；非公共领域作品缺作者信息时仍不显示。

首先尝试日语维基的精确条目/重定向和条目照片。缺图时，通用后备流程搜索 Wikidata：只有唯一且名称/别名精确匹配的实体才继续，绝不把相似或多个同名结果中的第一项直接当答案。读取该实体关联的 P18 实景文件；还没有时，读取实体 P373 对应的 Commons 分类，并用实体日/英名称及分类名过滤文件。每张图仍核对来源、作者、许可和图片域名，并排除地图、标志等文件。

原有最多8个地点/候选缓存/随机避免相邻重复保持。后备查询并发最多2处、总预算15秒、单处最多9秒；原查询最多9秒。遇到429至少退避60秒，避免连续重试压迫公共接口。已缓存的查询共享请求；用户主动“重新查找图片”可跳过之前的空结果缓存。只发送景点名称，不发送用户对话或会话令牌，不增加 Gemini 调用。

## 用户反馈

图片加载中保留占位。最终未找到时，在对应景点下显示“暂未找到可确认属于这处景点的实景照片。”；存在图片地址但加载失败时显示“这处景点的照片暂时加载失败。”。两种情况都提供“重新查找图片”，重新核对来源并尝试其他候选，不再静默留白。成功照片仍为景点介绍下的横图，不提供外部跳转。

公共图源不能保证每个景点都有可用照片；图名/实体匹配也不是模型视觉核验，不能承诺所有图片均为实时现状。本次通过通用授权修复和关联图库查询减少缺图，而不是为每个城市硬编码照片。

## 验证

50项手机测试、lint、TypeScript和实际iOS Metro包通过。覆盖日文公共领域授权、CC版本、唯一实体匹配/同名拒绝、关联Commons图片后备、缺图缓存与显式重试、已有照片随机/来源/限制和聊天行为。

真实跨地区查询8处全部成功：宇都宮二荒山神社、大谷資料館、姫路城、浅草寺、伏見稲荷大社、熊本城、札幌市時計台、首里城。此样本不能代表所有日本景点的可用率；真机网络环境及重试触摸仍需Expo Go复核。
