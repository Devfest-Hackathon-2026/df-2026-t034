# 景点参观资料：已完成范围与联网核实建议

日期：2026-11-09。状态：本地官方资料库已接入；自动联网部分为待批准设计，尚未编码、部署或调用。

## 当前可用

`japan-travel-mobile/src/lib/trip-admission.ts` 保存7处已审阅京都景点的名称/城市、参观状态、适用范围、例外、官方来源及人工核对日期。`trip-booking-links.ts` 先取得独立参观证据，再解析销售渠道；无法匹配 Trip.com 商品不等于需购票。`TripAdmissionInfo` 展示简短结论，可展开依据。此资料库的展示不调用 Gemini、Google Search 或 Places，无额外 token/搜索/图片请求。修改资料后需更新手机代码，尚无远程数据同步。

来源包括京都市观光协会免费景点FAQ、京都府鴨川公园页面、环境省京都御苑FAQ、宫内厅各设施参观指南。鴨川结论仅用于公共河岸一般散步；不用于收费餐饮、导览、活动等产品。京都御苑与苑内独立收费设施不混用；京都御所与需登记的京都仙洞御所、桂离宫不混用。网页规则可能变化，显示的核对日期不是未来出行日的可售保证。

## 建议的自动核实流程（未启用）

1. 官方资料库/有效缓存命中时直接展示，不重复查。
2. 未命中时由受现有匿名测试会话保护的服务端端点，对“城市+景点+参观项目+出行日期”做一次限定检索；不上传完整聊天、私人预订或个人资料。
3. 使用现有 Vertex Gemini 服务身份和 Google Search grounding。只接受匹配地点的景区运营方、政府或官方旅游局依据。保留支持具体结论的引用与核对日期；搜索摘要、无来源的模型回答、售票平台无库存不能单独证明免费。资料冲突或缺少明确证据时保持未取得可靠资料，不能为了取消“待确认”而编造结论。
4. 区分普通参观、付费子区域/交通、需登记但免费、预约/购票。Trip.com只有在准确商品已匹配时提供；否则用经过来源核验的官方预约或票务页，不打开通用首页冒充匹配成功。
5. 服务端持久化核实记录、调用限额及缓存，缓存键含城市、地点和项目/日期适用范围。建议成功资料7天复用、失败短期冷却，同地点并发合并。不得永久沿用过期结论，特殊日期或活动单独验证。具体提供方缓存/展示条款上线前核对。
6. 建议初始服务总量10次核实任务/日、每测试会话3次/日、并发1、一次SDK调用、不自动重试、20秒超时、最多2048输出token，并记录实际搜索查询次数。不占用Places图片额度。搜索失败不阻断已有行程或聊天。

以上**任务次数不是 Google 实际搜索查询次数的硬上限**：单次 grounding 可能触发多个查询；不能用10次任务推导固定每日费用上限。上线前须核对项目实际 grounding 查询限额/可设硬配额、月度剩余额度、模型可用性及提供方计费，不用预算提醒冒充自动停止收费。
